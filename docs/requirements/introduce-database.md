# データベース化

ドライブレコーダーの動画ファイルを、データベースで管理する。

現在は単にリモート (SMB サーバー) や USB 接続のリムーバブルメディアとして、数万件以上のドライブレコーダー動画ファイルが存在している。
これらのファイルを、 SQLite 上で管理する。
管理を行なう CLI を実装する。

## 仕様

- CLI は、複数のパスを候補として、設定ファイルを読み込む。
- データベースは CLI と同じマシンに存在する、ローカルの SQLite データベースである。
- Drizzle で O/R マッピングおよびマイグレーションを扱う。
- 一つのメインコマンド `dashcams` をベースとして、再帰的な構造を持つサブコマンドによって複数の機能を提供する。
- このシステムが実行されるのは Ubuntu サーバー上のみである。（接続先の SMB サーバー等は除く）
- CLI は設定ファイル（リポジトリルートの `config.toml` または `~/.config/dashcams/config.toml`）を読み込む。

## コマンド

- `dashcams storages add <id> <type> [接続先] --path <path>` でストレージの追加
- `dashcams files sync <storage-id>` で同期する（ファイル → データベースへの保存）
    - inbox フォルダの全動画ファイルを対象に、移動先 raw フォルダのパスを `raw_path` として登録し、その後実際に安全に inbox から raw に移動する、ということを行なう。（既に存在する場合は上書き。）

## ドメイン（エンティティ）

### ストレージ (Storage)

動画ファイルの保存先を扱う。

保存先の種類としては、

- ローカル
- リモート (SMB サーバー)
- （Ubuntu マシンに接続された）USB リムーバブルメディア

がある。それらの種類ごとに特定の役割を持つということはない。

`Storage` のフィールドとしては、以下を想定している。

- id: 登録時にユーザーが明示的に指定するヒューマンリーダブルなもの。
- 種類 (type): local, SMB, リムーバブルメディア
- 接続先（SMB サーバーの URL や, リムーバブルメディアのドライブ文字）
- 接続情報（SMB の場合に必要な資格情報）
- 格納フォルダのパス（動画ファイルは特定のフォルダ下に所定のサブフォルダをもうけて格納する。そのフォルダのパス。）

#### 格納フォルダ下のサブフォルダ

格納フォルダ下のサブフォルダは以下のとおり固定の名前を持つ。

- `inbox`: データベース管理前の動画ファイル。人間が放り込む。
- `raw` : データベース管理中の動画ファイル。 `sync` によって `inbox` から移動される。
- `optimized` : ffmpeg で圧縮済みの動画ファイル。 `optimize` によって変換・移動される。
- `archive` : 連結された動画ファイル

### 動画ファイル (VideoFile)

ドライブレコーダーの仕様上、実際には一連の撮影であっても、それらは一定時間ごとに個別のファイルとして保存される。
`VideoFile` は、そのファイルに対応して存在するものである。

フィールドとして以下を持つ。

- `id` (PRIMARY KEY): フォルダを含まないファイル名を ID とする。ドライブレコーダーがセットする動画ファイル名は動画ごとにユニークです。
- `mtime`: ファイルの `mtime`
- `raw_path`: ファイルのパス
- `raw_size`: ファイルサイズ (bytes 単位)
- `event_type`: イベント録画の種別。ファイル名から判別できる。種類は normal（非イベント録画）, 衝撃検知によるイベント録画、 switch （手動のスイッチによるイベント録画）
- `direction`: 撮影方向。前方 (front) または後方 (rear)。ファイル名から判別できる。
- `timestamp`: ファイル名から抽出できるタイムスタンプ（秒単位）
- `duration`: ffprobe による動画の長さ。ただし、丸めが発生しないような表現にしたい。

#### ファイル名の規則

ファイル名は、 orm.py で示される通り、必ず

`/^\d{8}_(\d{10})_(N|G|S)(F|R).MP4$/`

にマッチする。ファイル名の実例としては `00004929_2409141309_NF.MP4` が挙げられる。

- 第1キャプチャーはタイムスタンプとしてパースでき、 2けたの年、2けたの月、2けたの日、2けたの時、2けたの分からなる。秒は取得できないためデータベース上は秒を 00 で埋める。
- 第2キャプチャーイベントタイプとしてパースでき、 N は normal, G は衝撃検知, S は手動スイッチを意味する。
- 第3キャプチャーは撮影方向としてパースでき、 F は front,  R は rear としてパースできる。

よって、 `00004929_2409141309_NF.MP4` は、明らかに、 2024/09/14 13:09 に撮影された、非イベント録画の前方の動画として解釈できる。

### 動画 (Video)

`VideoFile` を連結してできる、実際の一連の撮影。現時点ではアプリケーションで扱わない。
